## The Diegesis decision (IB-HO-01)

The handoff asks to adopt Diegesis if a prototype proves it, or to record the blocked feature and use the smallest
local substitute. The pinned source (`c60c89b`) was inspected:

| Required capability | Diegesis at `c60c89b` |
| --- | --- |
| Keyboard target navigation (accessibility parity) | Not provided |
| A mode that does not move the camera | Not provided: the camera always flies to the scene |
| Station logic that keeps running while nobody is in the scene (attended batches, observers) | Ticks only while the station is in use |
| A published artifact this toolchain can resolve | None found (no Modrinth/Maven coordinate for 1.20.1 Forge 47.4.23) |

Decision: Brewing owns a local substitute. Part volumes are defined once on the server per facing
(`WorkshopParts`, `WorkshopGeometry`); the client picks parts with the same volumes, cycles them with the keyboard in a
fixed order and can optionally frame the camera (`client.workshop`). There is no Diegesis dependency, and the
`presentation` field of workshop profiles is reserved for a future presentation layer. See ADR-5 in
`docs/ARCHITECTURE.md`.

### Performance

`PerformanceGameTests.thirtyTwoActiveKettles` (integrated GameTest server, this host): 32 tended kettles and 8 observers
over 200 ticks, peak 32 reacting at once. Workshop work per tick: median 58 µs, mean 186 µs, p95 520 µs, p99 769 µs,
worst 893 µs. 2176 snapshots (6.8 per station per second, about 773 bytes each before compression); at most 0 notices
per player. These are single-host measurements, not a server capacity claim.

## Defects found and fixed during verification

| Defect | Cause | Fix and evidence |
| --- | --- | --- |
| Client stopped receiving block changes in a chunk after a station's presentation caught up inside a broadcast | `getUpdateTag()` refreshed the station's presentation, whose lifecycle transition called `sendBlockUpdated` from inside vanilla's chunk change broadcast; the re-entrant change stranded the section's change set, so later changes in that section were never sent | Lifecycle updates are owed and flushed from the station's own tick (`StationBlockEntity.sendUpdate`); `WorkshopRegressionGameTests.buildingAnUpdatePacketNeverMarksTheChunk`; smoke `block_sync_*` checks |
| A single click on the spout filled every bottle | A non-batch fill without an index fell into the fill-all branch | Only the batch action fills all; a click fills the next free bottle (server and practice) |
| Tools and trays drawn with the missing-texture checkerboard | The tool prism used `block/smooth_quartz`, which has no texture in 1.20.1 | Uses `block/quartz_block_bottom` |
| Hand hints shown unformatted; overlay text dark on dark; key hints over the hotbar | Placeholder indices beyond the arguments; light-panel palette colours on dark fills; hints at the HUD's height | Arguments and strings aligned; inset palette colours; hotbar, status bars and crosshair hidden while the view is open |
| "The batch sealed itself" shown for a manual seal | One message for both reasons | "Batch sealed (reason)" |
| Notebook pages and JEI texts still described minigames | Text not migrated | Rewritten in all five languages |
| One GameTest run crashed the test server | The new partial-bottling test dereferenced the station in a wait condition after a failed step; the per-station result counter in `TestSupport` was never reset although batches reuse structure positions | Null-safe wait; the counter is reset when a test places its kettle; two consecutive full passes afterwards |
| `brewing.finishingSeconds` no longer affected finishing | The physical fitting used a fixed 3 s settle while the plan screen showed the configured time | The settle is the configured time, snapshotted into the process when the batch is set out |
| Smoke harness gaps at small GUI sizes | The 1.1.1 compact layouts put Prepare/Finish and the plan route on a second page and turn the Notebook's chapter list into one cycling button; the harness clicked widgets that are not shown there | The harness opens the route page and cycles chapters in compact layouts (`ClientSmokeTest`, `VisualChecks.notebookTab`) |
| Smoke harness assumptions | The smoke world is creative (a bucket stays full, as in vanilla); a carrier in hand is used on a station instead of opening the view; a check ran before the station's first snapshot; a faked "adapter missing" hold is released by the periodic recovery re-check; a previous run's saved tutorial progress could be reloaded over the reset | Each step now waits for the real state or prepares it explicitly |

## Pending gates

These are **not** done and are not claimed:

- Real playtests: a new player completing a batch without help, repeated batches, each material family, satisfaction
  and fatigue (handoff 21, definition of done).
- A dedicated server with two real clients: shared tools, helper disconnect, late observer, station break during a
  transfer, 0/100/250 ms latency with jitter and reduced TPS.
- Native-language review of the new strings; narration listening tests.
- Shader and rendering combinations, moving-video review of the apparatus, audio listening review, wide/narrow aspect
  ratios and altered FOV beyond the automated GUI-scale runs.
- A refreshed full showcase set: only the four images that showed the 1.1 minigames and result screens were replaced.

## Known limitations

- Diegesis is not used (see above).
- `/reload` does not seal hands-on batches by design; a batch from 1.1 open in its original interface is sealed as
  before.
- The client smoke test logs one intermittent `IndexOutOfBoundsException` from vanilla container content handling when
  it opens the Apothecary Rack menu right after closing another menu with `setScreen(null)`; the same message appears
  in a 1.1.1 smoke log of 2026-11-02, and the rack checks that follow pass. It was not investigated further.
